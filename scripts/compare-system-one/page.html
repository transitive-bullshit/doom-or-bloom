Keep Jev. Use Clairic only to find the numbers and dates people state

We replayed the recorded interviews of all featured simulated users through three engine setups. Swapping Jev for Clef moved people on the map, changed which follow-up question came next, and ran about slower at the cost. Clairic helped with one narrow job: finding a probability or a date the person actually stated, which Jev then checks.

What Clairic adds, and where it slips

Clairic is good at finding things: a probability in any wording, where it was said, a year. It is poor at judging whether the person still holds that view, so in this setup Jev still picks every quote, Clairic only fills gaps, and each find goes through the same Jev check that guards today's quotes.

Which question comes next

At every recorded answer, we asked each engine which follow-up it would choose. A second Jev run picks the same question 91% of the time. Clef picks a different one about a third of the time, so live interviews would take a different path.

Speed and cost

Clef answers our 22 to 93 question batches in seconds where Jev takes a few hundred milliseconds, and it charges about six times more per token. Clairic is cheap and runs beside the existing result request.

Recommendation

How this was run
  • All 47 featured simulated users, using their selected production transcripts (read-only). Each transcript was replayed answer by answer through the real engine in persona mode, exactly as the published pages were built. No new answers were generated and nothing was written to a database.
  • Today: Jev 1.13.0 at algorithm 0.7.5. Jev + Clairic: Jev makes every judgment and picks every quote as today; Clairic runs beside the result request, proposes a stated P(doom) only when Jev found none, and dates the timelines Jev chose. Jev verifies each proposal before it is shown. Clef + Clairic: Clef answers every Jev question and Clairic picks the quotes, each verified by Clef. Clairic's own P(doom) and map estimates were recorded but never shown.
  • A fourth run let Clairic pick the quotes with Jev verifying them. It kept the map and P(doom) but showed fewer timelines (14 vs 22) and assumption quotes (90 vs 100), so the recommended setup leaves quote picking to Jev.
  • Reference readings are the benchmark consensus: an independent model reading each person's source dossier, and the simulated person placing itself. They are imperfect and share a model family, so read them as a fair yardstick, not ground truth. Public statements are the 15 verified P(doom) quotes among the featured users.
  • Clef and Clairic are previews. Both returned identical outputs on repeated identical requests; Jev varies slightly, which the second Jev run measures. Calls went through the Cloudflare command-line tool, which adds roughly 0.7 s per request; a production integration would use the REST API.
  • Adapting Clef took one change: it accepts only letters, digits, dot, dash and underscore in question IDs, so the adapter renames ours. It also caps a request at 64 questions and silently truncates long input instead of rejecting it.
  • Code: reference draft PR (not for merging) on branch spike/cloudflare-system-one; re-run with scripts/compare-system-one.ts and scripts/compare-system-one.py, as described in docs/research/cloudflare-system-one-spike-2026-10-20.md.
